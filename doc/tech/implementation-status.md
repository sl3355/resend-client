# Version 0.1 implementation and validation

Implemented on 2026-10-19; workspace support added on 2026-10-20. This is a developer preview of the first desktop version. The proposed product requirements remain the release contract; this document records implementation evidence and gaps rather than marking every requirement complete.

## Decisions and operating boundaries

- Retained Tauri 2 with React/TypeScript, a Rust service layer, direct Resend HTTPS access, OS-native credentials, SQLite WAL with FULL synchronization and FTS5, and private generated attachment paths. No hosted service, DNS changes, beta inbox dependency, production credential, or live email was used during implementation.
- Multiple named local workspaces, each backed by a stable profile UUID and its own OS-stored API key. Only one workspace is active; the selection survives restart. Schema v2 migrates existing profiles in place and enforces a unique active workspace. Mail, drafts, Outbox, identities, sync cursors, files, local flags, and appearance remain scoped to each profile. Disconnect retains the workspace and cached data while removing its credential. Restore activates a separate disconnected workspace. Credential replacement requires explicit same-account confirmation; independent team-identity attestation is not available in this preview.
- Workspace switching remounts the React mail view to discard prior selection, filters, search, and Undo callbacks. Scoped IPC carries an expected workspace UUID, checked under the same DB lock as mutations. Background sync stops between requests after switching. Send claims check the active profile atomically; already claimed submissions keep their original credential, payload, and profile through acceptance/error commits. Inactive workspaces do not automatically sync or send. Replacing credentials pauses previously attempted sends for review.
- Incoming and sent-history probes run independently and do not mutate Resend. Both must pass before secure credential persistence. A successful sent-history probe proves read access, not permission to send; sending permission/domain verification are confirmed only by an explicit send.
- Initial scans request 100 records per direction, run a fresh head scan independently of durable historical cursors, and continue at most two more pages per direction per cycle. Page upserts and cursor advancement commit together. All imports preserve local flags and tombstones. Background refresh runs roughly every 30 seconds while the process is running, with bounded body/status hydration; actual network duration and provider backoff affect this cadence.
- The shared request scheduler serializes requests at a conservative 4 requests/second, honors Retry-After, and returns longer backoffs to the queue without blocking the application. Quota errors pause affected sends instead of spinning. Transient retry delay currently uses a fixed minimum interval rather than exponential jitter.
- An immutable payload and send identity commit before submission. Submitting attempts recover as unknown. Retries reuse the original key and payload for at most 23 hours from the earliest attempt; expired/future clocks require review. A later permission failure does not turn an already unknown outcome into a definite rejection. Explicit draft copies pause the original attempt and warn about duplication. No exactly-once delivery guarantee is made.
- Email HTML passes through Rust Ammonia and frontend DOMPurify allowlists and an opaque-origin iframe with no scripts, forms, same-origin grant, navigation, images, CSS URLs, or privileged commands. Links are removed from the content document and presented as actual HTTP(S) destinations in trusted UI for explicit OS-browser opening. Remote and inline images are entirely blocked in this preview. There is no per-message image-loading feature yet.
- Native attachment selection/cache/save is bounded. Outgoing encoded payloads use a conservative 39 MB cap beneath Resend's documented 40 MB limit. Downloads accept only HTTPS on the documented inbound/outbound Resend CDN hosts, reject redirects, carry no API authorization header, and stop at 40 MB. An unknown provider storage host fails closed and needs a reviewed adapter update. The UI never automatically opens downloaded files.
- Backups are versioned JSON envelopes with SHA-256 integrity checks and base64 file content. They exclude credentials and transient provider URLs. Restore validates before using generated UUID file paths, stages attachments, imports within a transaction into a separate profile, and never automatically submits restored pending attempts. Checksums detect accidental corruption; they do not authenticate untrusted backups. Attachment data is limited to 250 MB on export and backup files to 512 MB on import.
- Composer and settings load on demand. The initial web bundle is approximately 300 KB before gzip, with the editor in a separate chunk. This is a bundle observation, not an application memory/startup benchmark.

## Verification performed

Host: macOS 27.0.1 (26A434), native ARM64. Node 24.19.0, Rust 1.99.1. JavaScript dependencies are exact-pinned; package-lock.json and Cargo.lock record the full resolutions. Major resolved native dependencies include Tauri 2.12.4, rusqlite 0.37.0, reqwest 0.12.28, keyring 3.6.3, and Ammonia 4.2.4.

- TypeScript and optimized Vite production build pass. Final automated suite: 21 Rust tests, 8 frontend unit tests, and 9 browser scenarios (38 total).
- Frontend unit tests cover Reply-To, own-identity exclusions, deduplication, Bcc privacy, RFC reference headers, forward attachment behavior, graph linkage/cycles, hostile markup, and restrictive reader CSP.
- Workspace regression tests cover schema-v1 migration/restart, one-active-workspace enforcement, stale command guards, equal draft IDs in different workspaces, inactive queues, switching during HTTP submissions, and cooperative sync pause. Browser tests cover workspace creation/rename, switching, draft/queue/identity isolation, last-active restart, cleared search/Undo, and small-screen access. Frontend adapter tests reject delayed saves/sends/settings for the previous workspace.
- Rust tests cover hostile HTML, header/address injection, null/unknown provider fields, page replay, local flags/tombstones, exact identity matching, composed FTS search, profile isolation, stale draft revisions, immutable send deduplication, crash recovery, safe retry clocks, redacted definite rejection, same-payload/key retries after a dropped connection, server backoff, revoked permissions after unknown outcomes, checksummed restore, transaction failure isolation, and retained attachment/thread metadata.
- Local HTTP contract fixtures exercise paginated import, repeated records, newly arriving mail, outbound activity, and persisted organization. These fixtures are not evidence of account-specific permissions or actual provider retention.
- Browser scenarios pass in installed Google Chrome: isolated reading without external requests, combined search filters, archive/Undo across restart, rich-draft recovery, recipient presence validation and demo queue/cancel, reply composition, appearance/focus containment, narrow-window navigation, and asynchronous confirmation cancellation. Browser tests exercise the explicitly marked demo adapter; they do not certify the Tauri IPC/native integrations.
- Optimized native ARM64 macOS .app builds successfully (about 18 MiB); binary architecture verified using `file`. Its local linker signature is ad hoc, with no Developer ID/notarization. It is a development artifact. The native app was launched successfully and created one disconnected schema-v1 profile with no sample messages.
- `cargo clippy --locked --all-targets -- -D warnings` and formatting checks pass. npm's production dependency audit reports zero known vulnerabilities against the official registry on this date. This does not certify all native/transitive dependencies or replace a security review.

## Remaining release work

Public release is blocked on the gates in delivery-and-validation.md. In particular: designate a live test account and allowlisted recipient; certify both native WebViews; finish backup/attachment/native dialogs and accessibility fault testing; build/test all four architectures on clean physical devices; select signing/update hosting; implement signed updater metadata, update verification and migration backups; and produce distribution license notices. CI currently uploads unsigned developer packages and does not publish releases or configure an updater.

Other preview limitations: no tray, notifications, mailto registration, autocomplete, permanent profile deletion UI, remote/inline image loading, raw .eml export, automatic forwarding of chosen cached source attachments, or multi-device organization. Conversations show reference-linked records in the loaded cache, not a complete provider-side mailbox thread graph. Search/labels are local. Provider history and bodies are limited by account storage/retention and safe reader/response size bounds.
